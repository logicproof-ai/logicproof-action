## ⚡ Quickstart

Add LogicProof AI to any repository in **5 lines of YAML**.

Create `.github/workflows/logicproof.yml` in your repository:

```yaml
name: LogicProof AI
on:
  pull_request:
    branches: [main, master, develop]

jobs:
  verify:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write # Required for posting certified patch comments
      security-events: write # Required if uploading SARIF to GitHub Code Scanning
    steps:
      - name: Checkout Source Code
        uses: actions/checkout@v4

      - name: Run LogicProof Verification
        uses: logicproof-ai/logicproof-action@v1
        with:
          api-key: ${{ secrets.LOGICPROOF_API_KEY }}
          bloquear-en: critica # "critica", "alta", "media", or "ninguna"
```

> **🔑 API Key Setup:** Retrieve your API key from the [LogicProof Dashboard](https://logicproofai.com/panel) and store it in your repository under **Settings → Secrets and variables → Actions → New repository secret** as `LOGICPROOF_API_KEY`.

## 🛠️ Action Inputs & Configuration

Customize the verification process with these optional inputs:

| Input | Description | Default | Required |
|---|---|:---:|:---:|
| `api-key` | Your LogicProof AI API Key. Always provide as a secret. | — | **Yes** |
| `ruta` | Subdirectory or file path to analyze. | `.` (entire repo) | No |
| `bloquear-en` | Minimum severity threshold that fails the CI check: `critica`, `alta`, `media`, or `ninguna` (audit mode: reports without failing). | `critica` | No |
| `comentar-pr` | Whether to automatically publish findings, counterexamples, and certified patches as a PR comment (`true` / `false`). | `true` | No |
| `sarif` | File path where SARIF 2.1.0 results should be saved (for GitHub Code Scanning integration). | `""` (disabled) | No |
| `version` | Specific binary version of the analyzer to run (e.g. `v1.3.3`, or `latest`). | `latest` | No |

### Action Outputs

| Output | Description |
|---|---|
| `hallazgos` | Total count of mathematically proven security and logic breaches. |
| `informe` | Absolute file path to the detailed raw JSON report generated by the engine. |

## 💬 Pull Request Experience

When LogicProof AI identifies a vulnerability or invariant violation, it comments directly on the Pull Request:
1. **Mathematical Proof:** Explains the exact path where unvalidated data reaches a sensitive sink.
2. **Exact Counterexample:** Shows the real input values that trigger the vulnerability.
3. **Certified Code Patch:** Proposes a unified diff that closes the flaw, re-verified through the Z3 SMT solver.
4. **Auto-PoC Reproducer:** Provides an executable `curl` command to verify the fix immediately.

```markdown
### 🛡️ LogicProof AI — Security Verification Alert

■ **`api/billing.ts:42`** · **CRITICAL** · `IDOR / Broken Object Level Authorization`
- **Taint Path:** External parameter `req.body.invoiceId` reaches `prisma.invoice.update()` without ownership validation.
- **Counterexample:** Triggered when `invoiceId` belongs to organization B while caller session belongs to organization A.

#### 🛠️ Certified Code Patch
The engine has tested this patch against the SMT solver; the breach is closed:
```diff
- await prisma.invoice.update({ where: { id: req.body.invoiceId }, data });
+ await prisma.invoice.update({ where: { id: req.body.invoiceId, organizationId: session.orgId }, data });
```

#### 🔬 Responsible Reproduction (Auto-PoC)
```bash
curl -X POST http://localhost:3000/api/billing/update \
  -H "Authorization: Bearer <CALLER_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"invoiceId": "victim_invoice_uuid"}'
```
```

## 🛡️ Native GitHub Code Scanning & SARIF

LogicProof AI outputs industry-standard **SARIF 2.1.0** format, integrating seamlessly into GitHub's native **Security → Code Scanning alerts** tab:

```yaml
name: LogicProof Security Scan
on:
  pull_request:
  push:
    branches: [main]

jobs:
  security-audit:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      security-events: write
    steps:
      - uses: actions/checkout@v4

      - name: Run LogicProof Engine
        uses: logicproof-ai/logicproof-action@v1
        with:
          api-key: ${{ secrets.LOGICPROOF_API_KEY }}
          sarif: results.sarif
          bloquear-en: ninguna # Let GitHub Code Scanning manage severity triage

      - name: Upload SARIF to GitHub Security Tab
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: results.sarif
```

## 🔒 Zero-Retention Privacy Guarantee

### Why this Action downloads a native compiled binary:
1. **Zero Code Upload:** Your source code **never leaves the GitHub Actions runner**. The analysis happens 100% locally on the virtual machine runner.
2. **No Heavy Dependencies:** You do not need to install Python, Clang, Z3, or 300MB of compiler packages. The action downloads a standalone native Linux executable cached across runs.
3. **Protected Intellectual Property:** Your code stays within your VPC or GitHub enterprise boundary. Only an encrypted license validation ping travels to LogicProof servers.

## ❓ Frequently Asked Questions

<details>
<summary><strong>Does this Action require self-hosted runners?</strong></summary>
No. It works out-of-the-box on standard GitHub-hosted <code>ubuntu-latest</code> runners, as well as self-hosted enterprise runners (Linux x86_64).
</details>

<details>
<summary><strong>How fast does the verification run?</strong></summary>
Because the engine is compiled native C/machine code with an embedded SMT solver and caches unchanged ASTs, typical runs on pull requests complete in <strong>2 to 15 seconds</strong>.
</details>

<details>
<summary><strong>Can I write custom business rules?</strong></summary>
Yes. Simply commit a <code>logicproof.yaml</code> file at the root of your repository defining your custom domain invariants (e.g. <code>@balance >= 0</code>). The action automatically loads it.
</details>
